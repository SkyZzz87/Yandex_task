# Задача 3

### 1. Возможные причины изменения показателя

* Данные за прошлый период могли быть обновлены или пересчитаны после первого просмотра дашборда.
* Могла измениться логика расчёта охвата или условия отбора данных.
* В таблице могли измениться значения `valid_from` и `valid_to`. Если дашборд использует эти даты для фильтрации актуальных записей, то после их изменения в расчёт могло попасть другое количество пользователей.
* При загрузке или синхронизации данных могла произойти ошибка.

### 2. Проверка одной гипотезы

Я бы проверил, не изменились ли значения `valid_from` и `valid_to` для данных за нужный период. Сначала сравнил бы их текущие значения с предыдущей версией данных, а затем проверил условие фильтрации по этим датам в SQL-запросе дашборда. Если даты или условие их обработки изменились, это могло привести к изменению количества пользователей в охвате.

### 3. Автоматическая проверка

Можно добавить автоматическую проверку, которая будет сравнивать значение охвата для уже завершённого периода с предыдущим расчётом. Если показатель изменился сильнее установленного порога или если изменились данные `valid_from` / `valid_to`, система должна автоматически отправлять уведомление команде, отвечающей за данные.
